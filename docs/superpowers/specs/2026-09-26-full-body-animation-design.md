# MECVR Full-Body IK and Animation Design

## Goal

Produce a complete, mod-owned humanoid pose every OpenXR frame from the HMD,
controllers, locomotion state, and grounded state. The pose must be deterministic
and testable without an HMD. It becomes game-visible only through a separately
proven Catalyst skeleton adapter; unknown retail memory is never written.

## Considered approaches

1. Patch a guessed Frostbite character pose immediately. This could become
   visible quickly, but an unproven layout risks corrupting the player or game.
2. Render replacement hands/body as a separate overlay. This avoids Frostbite
   animation internals, but duplicates geometry, complicates occlusion, and does
   not actually animate Faith's body.
3. Build a canonical humanoid pose layer, discover the retail bone palette with
   an observe-only probe, then add a fingerprinted adapter. This is selected. It
   keeps the solver reusable and makes every retail write evidence-gated.

## Canonical body model

The solver emits world-space poses for root, pelvis, chest, neck, head, left and
right shoulder/elbow/wrist/hand, and left and right hip/knee/ankle/foot. A
`BodyCalibration` owns stature and segment lengths. No retail offsets or bone
indices appear in the solver.

Tracked head and hands are authoritative. Pelvis height follows calibrated head
height with crouch clamping. Body yaw follows projected head forward and is
damped toward the average hand direction while moving. Arms use the existing
bounded FABRIK chain. Legs use analytic two-bone IK with outward knee poles.
Feet are generated by a deterministic gait oscillator driven by planar velocity;
idle feet remain planted, locomotion alternates swing, and airborne state keeps
both feet below the pelvis without ground locking.

## Mod-owned animation

`BodyAnimationState` selects idle, locomotion, crouch, airborne, and climb.
Selection is driven by head height, planar velocity, vertical velocity, and
controller trajectories. The first implementation owns idle, locomotion,
crouch, and airborne poses; climb remains an explicit state for integration with
the STRIDE gesture classifier. Animation output is procedural joint motion, not
a request to play a stock game animation.

Each `HumanoidPoseFrame` carries a monotonic sequence, sample time, state, joint
validity, and source flags. A latest-value mailbox transfers it without exposing
OpenXR types to consumers. Invalid tracking never overwrites a previously valid
retail pose.

## Catalyst integration

The M3B OpenXR worker builds the body frame beside camera and input state. A new
observe-only palette classifier examines mapped render buffers for runs of
finite affine 3x4 or 4x4 matrices, records stable buffer size/offset/fingerprint,
and correlates motion with controller/head input. It performs no writes.

A future writer is enabled only when a version-specific adapter proves all of:
executable identity, buffer size, matrix stride, palette count, stable bind
context, expected sentinel bones, and a fresh body frame. Any mismatch returns
the original data unchanged. The adapter maps canonical joints to discovered
Faith bone indices and preserves all unmapped animation bones.

## Testing and acceptance

Headless tests cover segment lengths, reachable and clamped limbs, left/right
symmetry, idle foot planting, alternating gait, crouch pelvis height, airborne
state, deterministic replay, mailbox freshness, finite outputs, and tracking
loss. Live smoke requires no HMD and must retain `state_fail=0` while the body
path stays dormant. Retail writing is not accepted until observe-only evidence
proves the exact palette contract on version 1.0.3.47248.

## Self-review

The design has no unresolved offsets, guessed bone indices, or hidden HMD
dependency. Solver completion and game-visible completion are separate gates;
the latter cannot be claimed from headless pose tests alone.
